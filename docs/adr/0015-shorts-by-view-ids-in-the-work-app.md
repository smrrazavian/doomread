# Shorts is told apart by view ids, looked up only in the Work app

YouTube can hold the Work (a podcast) and Shorts, in one package. So when YouTube is the Work app, only Shorts is Watched (#7). The package alone can't tell them apart, so `WatchService` now needs the window's node tree, and `canRetrieveWindowContent` is on. This changes what ADR 0014 said the service could do. The disclosure, in English and Persian, and the service's description in the system settings now say so.

What it looks at stays narrow. Dart sends `setWatching` the view resource ids to look for, by package. They come from `watchedScreens` in core, and only for the current Session's Work app. The service checks those ids with `findAccessibilityNodeInfosByViewId` and reports which ones are on screen, never any text. It also gets `typeWindowContentChanged`, because Shorts opens inside YouTube without a new window. Those events are checked at most every 500 ms, only for a package with ids to look for, and only when that package's window is the active one. Each change of (app, ids on screen) is reported once. Core decides: `WatchRules.isWatched` treats the Work app as never Watched, except for a `WatchedScreen` whose ids are on screen.

The rules are data. Shorts is any of `reel_recycler`, `reel_watch_player` or `reel_player_page_container`. These ids were captured with `uiautomator dump` from YouTube 21.42.243 on Shorts, on a normal video and on the home feed. Only the ids were kept, in `packages/core/test/layouts/`, and the core tests check the rules against them. `reel_time_bar` was left out because it's also on the normal watch page. When YouTube changes its layout, capture new samples and update `watchedScreens`. A channel that updates the rules between releases (design 7.1) isn't built yet. The ids are plain data in core, so one can feed them later without native changes.

The Work app is a device-local setting, keyed by Work id. Package names belong to the device, as the current Work does (ADR 0012). It isn't a journal payload, which would have needed a migration and sync changes. The user picks it on Reading, from the card that otherwise says "turn the phone face down". The design asks for that line only when the Work isn't on the phone.

# When Accessibility is off, usage access is polled from a foreground service

Android 17's Advanced Protection reportedly revokes Accessibility for apps that aren't accessibility tools, and some users won't turn it on. Urges still have to work then (#8). The design names the fallback: usage access (`PACKAGE_USAGE_STATS`) plus an overlay.

There is one seam with two sources. Both report through `Watch.foreground`, the same `doomread/watch` channel and the same `AppWatch.onForeground` in Dart, so `UrgeWatch` and core don't know which one is running. `WatchService` (ADR 0014) is one source. `UsageWatchService` is the other: it calls `UsageStatsManager.queryEvents` every second over the last five seconds and reports the app of the latest `ACTIVITY_RESUMED`, once per change. `FakeAppWatch` stands in for both in tests. Dart picks the source, in `pickWatchMethod` in `app_watch.dart`. Accessibility wins when it's on, because it's instant and can tell Shorts apart. Usage access is next, but only when display over other apps is granted too. Without either, nothing is watched. `UrgeWatch` asks for the grants at each change and when the app resumes, since the user grants them in the system settings. It then tells the edge to poll (`setWatching` with `poll`) only while a Session is open and usage access is the method.

"An overlay" means `SYSTEM_ALERT_WINDOW`. It's what lets Doomread start MainActivity from the background without a bound AccessibilityService. So the Urge is the same Flutter screen in both cases, not a second native overlay window. Without it, Android blocks the launch, so the fallback only counts as on when both grants are there.

Polling needs a process that isn't frozen. A cached app's process is frozen moments after the user switches away, which is exactly when the user opens Instagram. So `UsageWatchService` is a foreground service of type `specialUse`, with a silent, minimum-importance notification. It runs only while a Session is open with this method. The design steers away from `specialUse` for the Session timer, which doesn't need one. Here there is no other way to keep polling. On Google Play, the play flavour needs the special-use declaration, and Cafe Bazaar's policy on it has to be checked along with Accessibility (design, section 12).

Latency: the Urge comes up between about 1 and 2 seconds after the Watched app opens. That's the poll interval plus the time usage stats takes to log the event, against well under a second with Accessibility. Usage access also can't see inside an app. So with YouTube as the Work app, Shorts isn't told apart and YouTube raises no Urge at all. Watched apps says so while this method is on, and Settings shows which method is active.
